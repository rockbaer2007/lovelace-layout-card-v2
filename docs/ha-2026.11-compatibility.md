# HA 2026.11.0: dashboard editor source comparison

Reviewed on 2026-11-05 for Dashboard Layout Card V2 0.1.181.

Core 2026.11.0 pins frontend **20261028.4** in its [frontend manifest](https://github.com/home-assistant/core/blob/2026.11.0/homeassistant/components/frontend/manifest.json).

| Native HA contract | Previous V2 implementation | Correction |
| --- | --- | --- |
| `hui-view` assigns `path = ["views", viewIndex]` to the layout | Only the numeric view index was consumed | Reactive path property; current path takes precedence for Sections |
| `hui-section` and `hui-section-edit-mode` require a section path | Only `viewIndex` and `index` were assigned | Both receive `["views", viewIndex, "sections", sectionIndex]`, retaining legacy properties |
| `hui-grid-section` appends `"cards"` to that path when adding | Missing path could throw before opening the card dialog | The native section now receives a usable path |
| `hui-view-header` and `hui-view-footer` require the view path | Only `viewIndex` was assigned | Both receive the view path; fallback card editors receive the header/footer card slot |
| Generic `ll-create-card` without a path defaults to view-level cards | Sections inherited the generic floating button | Sections explicitly target their first section; older HA uses the native section button |
| Native masonry card options use full card paths | Base V2 layouts always used numeric tuples | Use the HA view path plus `"cards"` and the card index; retain tuples without the new API |

The original Thomas Lovén layout-card is a useful reference for the classic column/grid layouts, but does not provide our Sections V2 implementation. Its numeric card tuples are still normalized by HA 2026.11's compatibility helper; they are not the cause of the missing native section path.

- `test/sections-drag.html`: passed (cross-section move, sorting, empty source and unchanged sections).
- `test/sections-path.html`: passed (add to the second section, preserve existing cards and other views, header/footer paths, global add and legacy indices).
- Initial inspection found .177 on Core **2026.10.4**, frontend **20260930.5**. The user then updated the system.
- Live verification on .177 with Core **2026.11.0**, frontend **20261028.4**, passed on 2026-11-05 after a fresh full backup.
- A temporary dashboard contained two views and two Sections V2 sections, each with a marked existing card. Adding and then editing a Markdown card in the second section passed. The floating add button added a card to the first section. Both original cards and the other test view were preserved.
- Editing the header and footer cards passed. A full browser reload showed all saved changes in the correct locations.
- The test used the published 0.1.181 asset, verified against its release SHA256. The temporary dashboard and resource were removed. The three original resources were retained, the existing `Test für APP` dashboard was not edited, and three manual full backups remain after the user's specific approval to remove the oldest archive.
- The live check covers the flows above. Newer HA features such as nested sections or sidebar content were not exercised and are not certified by this test.
